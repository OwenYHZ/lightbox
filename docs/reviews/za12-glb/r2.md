## 3. 裁决

### A. 拨盘字号（cap 1.7 是否可行）— 可行，但必须换窄体

你的算术对，前提错：你按 **常规 Helvetica（数字 0.556em）** 算 "5.6" = 5.5mm，所以觉得装不下。官方不是常规体：

- p1 用"盘径/柱径"互校（盘 200px、柱 Ø5.2=63px，比值 3.17 ≈ v2 的 3.14）→ p1 拨盘确为 Ø16，13.75px/mm。
- 同一标定下："11" cap ≈ 28px = **2.0mm（0.125×Ø）**；"5.6" 串宽 ≈ 33px = **2.4mm** → 单字宽 0.8mm = 0.4×cap = **0.29em（窄体，约常规体的 52%）**。
- 左盘 6 标签跨 141°、r=5.85 → 步长 2.76mm；窄体下 cap 2.0 的 "5.6" = 2.56mm，**刚好塞进 2.76mm 步长**（官方图上标签就是几乎相切，不是留大空）。

所以：**横向压缩 scaleX ≈ 0.55**，然后
- 左盘 cap **2.0**（现 1.20，1.67×）
- 右盘外环 cap **1.7**（现 0.84，2.0×；"-1/64" 5 字 = 3.6mm，外环 7 标签跨 210°、r=6.3 步长 3.85mm，刚好）
- 右盘内环 cap **1.9**（现 0.92）

只加 cap 不压宽必重叠——这点你的判断没错；压宽后 1.7 不但是"可行"，还低于官方。

### B. 底面 UV 要不要按物理方向翻回来 — **不要动**

`render_views.py` 的 bottom 相机是绕 X 转 π，**不产生镜像**：实测 bottom.png 里 X=−8 的热靴落在图左、X=+16.7 的 QR 落在图右，与"图像右=+X"一致。也就是说 bottom.png 现在读起来是正的，GLB 里的底面就是对的，**再翻一次反而会镜像**。以后别用"相机镜像"这个前提做补偿，用"热靴在左 / QR 在右"两个锚点验证即可。

### C. GLB 体积 6.4MB — 压到 ≤3MB

页面是 three.js 直接加载 GLB，首屏 6.4MB 偏重。建议：
1. 菲涅尔网格 340×96 → **220×64**（环纹周期 1.2mm，220 段 = 0.12mm/段，仍够），面数降到 ~1/2.6；
2. 菲涅尔与 Tube/WinGlass 合并成 1 个 mesh（少 2 个 draw call）；
3. 拨盘 120 齿 ×2 盘 = 2880 面，可保留（这是外观特征）；
4. 贴图：plate 2048×1820 可降到 1536×1365（看不清差别），dials 1024 保留；
5. **不要用 Draco**（除非前端已配 DRACOLoader），用 export 的 `export_draco_mesh_compression_enable=False`。
